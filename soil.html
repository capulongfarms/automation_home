Record a test by hand

The fallback path: for a sample taken before the field unit was built, a reading the unit failed to capture, or a correction to one it got wrong. The reading's identity is plot + timestamp — saving the same plot and minute twice corrects the existing record instead of creating a second one.

Import a CSV

For backfilling a batch of readings, or restoring from an export. Expected columns (header row required, extra columns ignored): takenAt, plot, moisture, temp, ec, ph, n, p, k, salinity, fertility, note. takenAt accepts YYYY-MM-DD HH:MM or an epoch in seconds. Rows that already exist are skipped, not duplicated.

Waiting on the field unit

The field unit runs on a Hankerila HKL-ER6-S3, which carries its own RS485 transceiver, a battery-backed DS1307 clock and an OLED — so no MAX3485 or DS3231 is needed. The ESP32-C3 Super Mini build is kept alongside it for a pocket-sized version later. This tab fills in on the unit's first sync; until the probe is wired, Add and CSV import keep the page usable.

Data contract

What the ESP32 must write, once it exists. Document IDs are deterministic, which is what makes re-uploading a queued reading harmless.
Reading document 
path: devices/soil_tester/readings/{readingId}

readingId = "<deviceId>-<takenAt>-<seq>"
            e.g. "soil1-1790000123-0004"
            seq is a counter persisted in LittleFS so it
            survives power-off; without that, two samples
            in the same second would collide.

{
  id:         "soil1-1790000123-0004",
  source:     "esp32",
  deviceId:   "soil1",
  plot:       "North Paddy",
  takenAt:    1790000123,        // epoch seconds, from the onboard RTC
  uploadedAt: serverTimestamp(), // set on write, not on capture
  moisture:   34.2,              // %
  temp:       27.8,              // degrees C
  ec:         420,               // uS/cm
  ph:         6.4,
  n:  48, p: 22, k: 130,         // mg/kg
  salinity:   210,               // mg/kg
  fertility:  62,                // 0-100
  battery:    0,                 // 0 = not measured on this board
  note:       ""
}

Offline queue and sync rules 
1. Capture writes one JSON line to /queue.jsonl in LittleFS,
   with its readingId already assigned.

2. On WiFi, walk the file line by line and setDoc() each
   reading at its own id. setDoc is idempotent: a reading
   that was already uploaded simply overwrites itself with
   identical content, so a retry can never duplicate.

3. Delete a line only after its write is confirmed. A reboot
   mid-sync re-sends a few readings; step 2 makes that safe.

4. Compact /queue.jsonl once every line is confirmed, rather
   than rewriting the file per reading.

5. Never trust millis() for timestamps. takenAt comes from
   the onboard RTC at the moment of capture, so a reading that
   sits queued for three days still carries the time it was
   actually taken.
